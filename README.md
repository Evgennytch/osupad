# osu! keypad — RP2040-Zero

Прошивка и Windows-конфигуратор для самодельного трёхкнопочного osu!-кейпада на Waveshare RP2040-Zero. Плата работает как USB HID-клавиатура, а параметры задаются через USB CDC.

**Скачать конфигуратор:** [release/osupad.exe](release/osupad.exe) · **Собрать из исходников:** [инструкция ниже](#конфигуратор)

> English: A three-button osu! keypad firmware and Windows configurator for Waveshare RP2040-Zero. The device exposes a USB HID keyboard and a USB CDC serial interface.

## Возможности

- Три независимые кнопки на GP0, GP1 и GP2; каждая замыкает вход на GND.
- Настраиваемые назначения клавиш, частота сканирования GPIO, debounce и цвет встроенного NeoPixel.
- Совместная работа USB HID клавиатуры и USB CDC конфигуратора.
- Сохранение конфигурации во Flash с проверкой magic, версии и checksum.
- Настольное приложение с поиском платы, выбором COM-порта и системным треем.

## Сборка и загрузка прошивки

1. Установите Arduino IDE 2.x и ядро **Raspberry Pi Pico/RP2040 by Earle F. Philhower**.
2. В Arduino IDE откройте папку `osupad` как скетч.
3. Выберите плату **Waveshare RP2040 Zero**.
4. В **Tools → USB Stack** выберите **Adafruit TinyUSB**. Вариант **Pico SDK** и **Adafruit TinyUSB Host** для этого проекта не подходят.
5. Установите библиотеку **Adafruit NeoPixel** через Library Manager. Adafruit TinyUSB входит в ядро RP2040 и выбирается пунктом USB Stack.
6. Соберите и загрузите `osupad/osupad.ino`.

При ошибке `TinyUSB is not selected` проверьте выбранные плату и USB Stack. В команде компилятора должен присутствовать `-DUSE_TINYUSB`.

## Конфигуратор

Для готового Windows-приложения скачайте [`release/osupad.exe`](release/osupad.exe) и запустите его. При первом подключении выберите «Автопоиск» или COM-порт платы. Окно можно свернуть в трей; выход выполняется из меню значка.

Запуск приложения из исходников (Python 3.10+):

```powershell
py -m pip install customtkinter pyserial pystray pillow
py app.py
```

Пересборка отдельного EXE (дополнительно нужен PyInstaller):

```powershell
py -m pip install pyinstaller
py buildprog.py
```

Готовый файл будет создан в `release/osupad.exe`. Временные файлы сборки сохраняются в `build/` и исключены из Git.

## Пины и настройки

| Сигнал | Пин | Подключение |
|---|---:|---|
| K1 | GP0 | `INPUT_PULLUP`, кнопка между GPIO и GND |
| K2 | GP1 | `INPUT_PULLUP`, кнопка между GPIO и GND |
| K3 | GP2 | `INPUT_PULLUP`, кнопка между GPIO и GND |
| NeoPixel | GP16 | Встроенный светодиод |

Допустимые настройки:

| Параметр | Значения | Действие |
|---|---|---|
| Клавиши K1–K3 | печатный ASCII 32–126 | HID-клавиши для кнопок |
| HZ | 125, 250, 500, 750, 1000 | Целевая частота программного сканирования GPIO |
| DEB | 0–10 мс | Интервал стабильности уровня для нажатия и отпускания |
| RGB | 0–255 на канал | Цвет NeoPixel |

Заводские значения: `z/x/c`, 1000 Hz, 0 ms, RGB `0,80,255`. При `DEB=0` фильтр выключен. Для контактов с заметным дребезгом начните с 1 мс и подберите значение по результатам проверки.

### Что означают частоты

`HZ` задаёт частоту чтения GPIO, а не частоту USB-опроса. При настройке 1000 Гц целевой шаг чтения — 1 мс; реальный шаг зависит от выполнения цикла и обслуживания USB/Serial. Принятое изменение сразу формирует HID report. HID endpoint объявлен с интервалом 1 мс для Full Speed USB; это ограничение дескриптора, а не измерение фактической доставки хостом. End-to-end задержка также включает debounce, ожидание USB poll и обработку ОС/игрой.

Все три нажатые клавиши формируются совместно в одном keyboard report. Отпускание одной кнопки сохраняет остальные удерживаемые. Отчёты отправляются при изменении состояния; отдельной очереди событий нет. Явное сохранение настроек вызывает запись в Flash, которая может кратковременно приостановить выполнение RP2040.

## Serial-протокол

USB CDC работает на 115200 baud. Команды заканчиваются `LF`:

```text
PING
GET_CONFIG
SET:K1=122,K2=120,K3=99,HZ=1000,DEB=1,RGB=0,80,255
```

Ответы включают `PONG`, `OK`, `ERR:...` и строку конфигурации:

```text
CFG:K1=122,K2=120,K3=99,HZ=1000,DEB=1,RGB=0,80,255
```

`SET` должен содержать каждое поле ровно один раз. Некорректная команда отклоняется целиком. При отсутствующей или повреждённой сохранённой конфигурации прошивка восстанавливает значения по умолчанию.

## Проверки

Запустить host-side тесты модели debounce:

```powershell
py -m unittest -v test_debounce.py
```

Они проверяют одиночное нажатие/отпускание, быстрые повторные нажатия, дребезг и нулевой debounce. Эти тесты проверяют модель алгоритма, но не заменяют аппаратную проверку платы.
